# 循星硬件产品家族手册

> 内部规划稿。本文描述产品之间如何组合、安装和运行。具体电气参数、认证和施工要求必须在硬件定型后由正式规格书替代。

## 1. 手册适用范围

本文面向：

- 产品与工业设计团队
- 硬件、嵌入式和平台研发
- 方案、售前与项目交付
- 安装、调试和运维人员
- 官网与采购资料编写人员

本文不替代电气施工图、医疗器械说明、消防规范或项目验收文件。

## 2. 系统关系

一个完整部署不是单台主机，而是以下链路：

```text
Sense / Control
空间感知器、离床感知器、门磁、墙面场景面板、床旁呼叫器
        │
        ▼
Connect
Matter、Thread、Zigbee、RS485、KNX、BACnet
        │
        ▼
Compute
Home Box / Community Gateway / Enterprise Stack
        │
        ▼
Act
照明、窗帘、暖通、干接点与护理工单
        │
        ▼
Record
状态、规则、执行结果、人工确认与审计记录
```

Compute 负责状态与规则，Sense 只提供必要输入，Act 只执行授权动作。任何单一传感器不得直接控制高风险执行器。

## 3. 产品家族设计规范

### 3.1 材质与颜色

- 主面板：暖白色哑光陶瓷感材料。
- 结构件：自然色喷砂铝。
- 状态灯：细窄冰蓝灯带，仅表达状态，不承担装饰照明。
- 标志：图形部分使用无色、低对比、浅内嵌浮雕。
- 第三方设备：不强行覆盖原厂标志；通过安装件、标签和界面保持项目一致性。

### 3.2 外观层级

- 主产品可在顶面或正面保留一个小型浮雕标志。
- 安装型传感器的标志应位于角落，正常观察距离下不明显。
- 机柜设备的标志不得占据通风区或服务面板中心。
- 接口、螺丝和散热区尽量布置在背面、底部或侧后方。

### 3.3 状态灯定义

状态灯含义必须跨产品一致：

- 熄灭：正常运行且无需提示，或未供电。
- 缓慢白色呼吸：启动或配置中。
- 冰蓝常亮：已连接且正在执行明确操作。
- 琥珀色：需要检查配置、网络或传感器。
- 红色：仅用于需要人工处理的故障或高等级现场事件。

最终颜色、频率和无障碍要求应在电子与交互设计阶段冻结。

## 4. 部署原则

### 4.1 本地优先

- 房间状态、基础规则和关键执行默认在现场节点运行。
- 公网不可用时，已配置的照明、呼叫和现场告警继续工作。
- 远程通知和外部模型属于可选依赖，不能作为关键链路唯一实现。

### 4.2 最小权限

- 每个传感器只上报完成业务所需的状态。
- 每个执行器只开放项目确认范围内的动作。
- 插件安装前声明读取、写入和外部连接权限。
- 管理员、护理员、家属和住户使用不同访问范围。

### 4.3 人工接管

- 墙面控制、实体开关和设备原有控制入口必须保留。
- 高风险动作必须支持确认、暂停和人工接管。
- 系统故障不得阻断消防、紧急呼叫或原设备安全保护。

## 5. 单品使用说明

### 5.1 Home Box

安装位置：

- 通风良好的桌面、柜内托架或弱电箱专用位置。
- 避免密闭金属箱、持续高温、潮湿和强电干扰源。

接入内容：

- 家庭网络
- 多协议接入网关
- 空间感知器与墙面场景面板
- 项目确认范围内的照明、窗帘、暖通与安防设备

运行要求：

- 使用独立电源，重要场景建议配置短时后备供电。
- 保留背面接口检修空间。
- 更换设备前导出配置和本地记录。

故障策略：

- 公网中断：本地规则继续运行。
- 多协议接入网关离线：停止向对应设备下发新动作，保留原设备手动控制。
- 主机故障：执行器进入项目定义的安全状态。

### 5.2 Community Gateway

安装位置：

- 楼层弱电柜、设备间或仅授权人员可进入的管理空间。
- 需要稳定供电、散热和有线网络。

接入内容：

- 房间节点和传感器
- 值班通知与工单系统
- 楼层照明、呼叫和低压执行模块

运行要求：

- 按楼层、组织和住户隔离数据。
- 网络、存储与告警队列需要监控。
- 规则升级应分批发布，并保留回滚版本。

故障策略：

- 单房间节点离线不得影响其他房间。
- 网关离线时，房间节点继续执行本地基础规则。
- 未送达的通知应记录失败原因并按项目策略重试。

### 5.3 Enterprise Stack

安装位置：

- 标准 19 英寸机柜。
- 满足设备功耗、散热、接地、网络分区和维护空间要求。

接入内容：

- Community Gateway
- 身份、权限和站点配置
- 医院或机构内部接口
- 本地模型、审计与运维服务

运行要求：

- 使用项目批准的 GPU、存储和冗余方案。
- 管理网络与业务网络分离。
- 系统升级、模型更新和接口变更均需留存记录。

故障策略：

- 计算服务异常不应影响房间级基础控制。
- 外部接口失败进入重试或人工处理，不丢弃原始事件。
- 备份恢复必须在交付前进行演练。

### 5.4 空间感知器

安装建议：

- 根据毫米波覆盖范围选择墙装或顶装位置。
- 避免被大型金属物、厚窗帘或持续摆动设备遮挡。
- 不正对空调出风口、风扇和强振动源。

调试内容：

- 覆盖区域
- 存在、离开和低位静止阈值
- 环境传感器偏差
- 房间空置时的误触发

维护要求：

- 房间家具布局变化后重新校准。
- 固件升级后复核关键事件。
- 只保存结构化状态；连续音频和图像能力默认关闭。

### 5.5 离床感知器

安装建议：

- 按厂商要求固定在床垫下或床架指定位置。
- 不影响护理床升降、床垫更换和日常清洁。
- 线缆不得形成绊倒、夹伤或缠绕风险。

调试内容：

- 在床、离床和回床识别
- 翻身、坐起与护理操作的排除
- 不同体重与床垫条件
- 断连和传感器移位告警

边界：

- 不输出诊断结论。
- 不以单一床传感器结果直接判断跌倒。
- 事件应与空间感知器、时间阈值和人工确认共同组成闭环。

### 5.6 墙面场景面板

安装建议：

- 采用常用开关高度，照护场景需考虑坐姿和轮椅使用。
- 常用控制应可盲操作并有明确触觉反馈。

交互要求：

- 单击、长按和旋转动作保持跨房间一致。
- 当前状态、执行中和失败反馈必须可区分。
- 断网时至少保留项目指定的照明或呼叫功能。

### 5.7 床旁呼叫器

安装建议：

- 住户躺卧和坐起时均可触达。
- 固定方式不得影响护理操作和紧急撤离。

交互要求：

- 按下后明确反馈“已接收”，不能只提示“已发送”。
- 未送达时触发现场备用告警。
- 关闭事件必须由授权人员确认。

边界：

- 不替代项目已有的法定紧急呼叫系统，除非产品与系统已完成对应认证和验收。

### 5.8 多协议接入网关

安装建议：

- 根据无线覆盖和有线总线位置部署。
- 与大功率电源、变频器和金属屏蔽体保持适当距离。

调试内容：

- 协议网络建立与设备登记
- 型号、固件和能力映射
- 状态读取、动作下发和失败反馈
- 断电重启、掉线与重新入网

维护要求：

- 兼容清单精确到型号与固件版本。
- 固件升级前备份设备映射。
- 未验证设备不得默认开放写入权限。

### 5.9 配电箱回路控制器

安装要求：

- 由具备资质的人员安装在配电箱或楼控柜中。
- 强弱电隔离、线径、接地、保护器件和散热必须符合项目规范。
- 每个回路保留清晰、耐久且可核对的标识。

调试内容：

- 输入与输出回路对应关系
- 继电器、调光、电机和干接点动作
- 手动旁路
- 失联、断电和重启后的安全状态

边界：

- 不接管消防、应急照明和生命安全系统。
- 不绕过设备原有保护器件。
- 负载类型和额定参数必须以正式硬件规格书为准。

## 6. 项目实施流程

### 6.1 勘察

确认房间数量、网络、供电、弱电箱、设备协议、护理流程和现有系统接口。

### 6.2 设计

输出：

- 设备点位图
- 网络与供电拓扑
- 设备和固件兼容清单
- 角色与权限矩阵
- 事件、动作与告警规则
- 断网和故障策略

### 6.3 安装

- 核对设备编号与房间编号。
- 按施工文件安装主机、传感器、控制器和执行器。
- 拍摄隐蔽工程和安装结果，进入项目档案。

### 6.4 配置

- 登记站点、楼层、房间和设备。
- 建立传感器、规则和执行器映射。
- 分配管理员、护理员、家属和住户权限。

### 6.5 调试

逐项验证：

- 正常触发
- 误触发
- 未执行
- 设备掉线
- 网络中断
- 主机重启
- 人工接管
- 记录与导出

### 6.6 验收

验收指标由项目双方确认。不得仅以演示成功代替连续运行、故障恢复和权限检查。

### 6.7 交付

交付内容至少包括：

- 实际设备清单与序列号
- 安装点位和网络拓扑
- 软件、插件和固件版本
- 权限账号与移交记录
- 兼容清单
- 备份与恢复文件
- 培训、验收和遗留问题记录

## 7. 运维与生命周期

- 每台设备记录型号、序列号、安装位置、固件和责任方。
- 插件、规则和固件版本必须可追溯。
- 远程维护需经项目授权并记录开始、结束和变更内容。
- 设备替换不得破坏历史记录与房间映射。
- 停产、停止支持和安全更新期限应提前通知。
- 第三方设备的保修与更换责任在采购文件中明确。

## 8. 安全与宣传边界

### 8.1 电气安全

强电、调光、电机、暖通和机柜设备必须满足项目所在地的认证与施工要求。规划稿中的接口数量和负载能力不能用于施工。

### 8.2 照护与医疗

- 可以描述“离床事件”“低位静止风险”“护理工单”和“处置记录”。
- 未完成对应注册和验证前，不得描述为医疗诊断、生命体征监护或保证防止跌倒。
- 任何风险事件最终由护理或医疗人员确认。

### 8.3 隐私

- 默认不使用摄像头。
- 声学感知默认输出事件，不保存连续录音。
- 家属端只提供授权摘要，不开放原始感知数据。
- 数据留存周期、导出和删除策略在项目文件中确认。

## 9. 官网产品页建议结构

正式加入官网时，建议采用以下顺序：

1. 三档计算平台：Home Box、Community Kit、Enterprise Stack。
2. 产品家族：Sense、Control、Connect、Act。
3. 六个核心配套产品及统一工业设计图。
4. 住宅、照护房间和机构三个标准组合。
5. 自研、生态选型与路线图状态说明。
6. 安装、隐私、安全和兼容边界。
7. 规格表、兼容清单和项目咨询入口。

官网不得展示尚未确认的售价、认证标志、性能指标或交付时间。
